## Контракт визуальной интеграции
Opus сначала определяет имена действий и состояние бойца без привязки к художественному скелету.
Codex определяет имена костей, сокеты кулаков, масштаб, ориентацию и правила экспорта.
Оба фиксируют соглашение в ROBOT_VISUAL_CONTRACT.md.
Контракт содержит idle, guard, left/right straight, dodge, hit reaction и knockout.
Для каждого состояния указаны владелец тайминга, начало, конец и допустимые прерывания.
Авторитетная активная фаза атаки принадлежит правилам Opus.
Визуальная анимация Codex должна совпадать с активной фазой, а не создавать вторую независимую систему урона.
Искры и реакции запускаются от подтверждённого события контакта из игровой логики.
Изменение скелета требует проверки сокетов и анимаций, но не должно молча менять правила попадания.
HUD получает read-only снимок здоровья, выносливости, времени, раунда и статуса трекинга.
Меню отправляет команды через согласованный интерфейс, не создаёт собственную копию матча.
Система настроек Opus является источником данных; UMG Codex — представлением и способом изменения.
## Протокол передачи результата
Передавай краткий отчёт с идентификатором задачи и версией исходного контракта.
Перечисли изменённые файлы и необходимые действия импорта или сборки.
Укажи точный commit или иной воспроизводимый снимок результата.
Добавь проверенное поведение и отдельно непроверенные пункты.
Приложи необходимые логи и скриншоты без пользовательских видеозаписей.
Если ассет зависит от конкретного скелета, укажи его путь и версию.
Если изменён экспорт, приложи обновлённый скрипт, а не только готовый бинарный файл.
Получатель сначала проверяет контракт и совместимость, затем выполняет интеграцию.
Получатель не переписывает чужие файлы ради собственного стиля кода.
Ошибка чужой области возвращается её владельцу с воспроизводимым сценарием.
Если агент недоступен, второй продолжает независимую работу; не подделывает его отчёт.
## Одновременная работа и Git
Предпочитай отдельные рабочие копии или Git worktree для независимых изменений текста и исходников.
На одном Windows-компьютере достаточно по очереди открывать редактор и запускать тяжёлые проверки.
Не запускай параллельные Unreal-процессы на одну рабочую копию проекта.
Не открывай один .blend на запись двумя процессами.
Не разрешай автоматическое слияние .uasset, .umap и .blend как обычных текстовых файлов.
Для бинарного конфликта выбери владельца и повтори генерацию или импорт из воспроизводимого источника.
Не загружай кэши, промежуточные сборки или записи камеры в обычный Git.
При использовании Git LFS заранее проверь лимиты и стоимость сервиса.
Не подключай платный сервис хранения автоматически.
После передачи закрывай редактор до интеграции изменений другого агента.
Определённый проектом механизм блокировки редактора должен иметь одного владельца, отметку времени и очистку после сбоя.
## Первая последовательность совместной работы
Opus проверяет Windows-среду и создаёт открывающийся C++-проект.
Opus фиксирует контракт позы, действий, сокетов и минимального игрового состояния.
Codex создаёт тестового оригинального робота, скелет и Blender-экспорт по этому контракту.
Opus реализует трекинг и принимает тестовую позу в Unreal.
Codex подключает визуальную позу, IK и первые анимации.
Opus подключает грушу, контакты и правила прямых ударов.
Оба передают результаты интегратору; интегратор проверяет путь от камеры до подтверждённого удара.
Opus доводит одиночный матч до конца с временными материалами.
Codex улучшает арены, материалы, свет, эффекты, камеру, меню и выход бойцов.
Opus собирает полную Windows-версию, а Codex проверяет визуальный результат этой сборки.
## Граница доступа к компьютеру
Этот чат сейчас работает на macOS; доступ к Windows-компьютеру с RTX 3050 не считается установленным.
Codex может подготовить и проверить доступные скрипты здесь, но запуск на Windows должен выполняться там.
Предпочтительный способ: открыть репозиторий в Codex на самом Windows-компьютере и запустить Claude Code там же.
Альтернатива: переносить согласованные коммиты и запускать подготовленные скрипты на Windows.
Для прямой работы из текущего чата нужен реально доступный и разрешённый удалённый инструмент.
Установка Unreal Python-плагина на Windows сама по себе не создаёт соединение с этим чатом.
Не заявляй, что Opus запущен или получил сообщение, пока это не произошло через реальный доступный инструмент.
