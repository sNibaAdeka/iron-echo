# Как подключить Unreal Engine к совместной работе Codex и Opus

Для этого проекта «подключить Unreal» означает дать локальному агенту доступ к папке проекта, запуску редактора, сборке и редакторским скриптам. Выбор модели в чате сам по себе такой доступ не создаёт.

Сейчас этот чат работает на macOS. Windows-ПК с RTX 3050 ещё не подключён; команды ниже предназначены для выполнения на том компьютере. Ничего из перечисленного не считается установленным только потому, что инструкция готова.

## Рекомендуемая схема

```text
Windows-ПК: i5-12400F / RTX 3050 / 32 ГБ
  ├─ Codex: графические скрипты и ассеты
  ├─ Claude Code + Opus 5.5: трекинг, бой и сборки
  ├─ общий Git-репозиторий и контракты
  ├─ Blender: создание и экспорт моделей
  └─ Unreal Editor: импорт, сцена, анимация и проверки

Во время игры:
  камера → отдельный MediaPipe runtime → localhost → игровой код Unreal
```

Если оба агента работают локально на этом Windows-ПК, не нужно открывать редакторские команды через интернет. Если Codex остаётся на Mac, передавайте изменения через репозиторий; для прямого удалённого управления потребуется отдельно настроенный доступный инструмент.

## 1. Установить или проверить Unreal и C++ toolchain

Через Epic Games Launcher установи одну подходящую стабильную версию Unreal Engine либо используй уже установленную совместимую версию. Не устанавливай сразу несколько версий.

Для нашего C++-проекта установи совместимую с выбранным Unreal версию Visual Studio. В Visual Studio Installer нужна нагрузка **Game development with C++**, а также подходящие MSVC и Windows SDK. Версии нужно сверить с таблицей Epic; простая установка VS Code не заменяет компилятор. [Таблица совместимости Epic](https://dev.epicgames.com/documentation/en-us/unreal-engine/setting-up-visual-studio-development-environment-for-cplusplus-projects-in-unreal-engine), [инструкция Microsoft](https://learn.microsoft.com/en-us/visualstudio/gamedev/unreal/get-started/vs-tools-unreal-install).

Создай или попроси локального Opus создать небольшой **Games → Blank → C++** проект с именем IronEcho. Ray tracing для исходного проекта не нужен. Пример корня — `D:\Games\IronEcho`; буква диска выбирается по реальному наличию места.

До любой автоматизации нужно убедиться, что проект открывается, пустая сцена запускается и C++ target собирается. Опиши найденные пути в локальном конфиге, а не зашивай их в скрипты для всех пользователей.

## 2. Включить автоматизацию редактора

В проекте открой **Edit → Plugins**, включи **Python Editor Script Plugin** и **Editor Scripting Utilities**, затем перезапусти редактор. Это проектные плагины. Они позволяют выполнять редакторские задачи — импорт и подготовку контента. [Документация Epic](https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python).

Положи приложенный `ue_connection_probe.py` в `Tools\Unreal\Integration` проекта. В редакторе выбери **File → Execute Python Script** и запусти этот файл. В Output Log появятся сообщения с меткой `IRON_ECHO_PROBE`. Это проверка выполнения Python, не готовый удалённый мост. Она не меняет сцену.

Можно выполнить файл из Output Log в режиме Cmd:

```text
py "D:/Games/IronEcho/Tools/Unreal/Integration/ue_connection_probe.py"
```

Замени путь на реальный. Если сообщения нет, проверь включение плагина, перезапуск и сам путь; не продолжай с предположением об успешной связи.

**Python Unreal предназначен для редактора и не является runtime игрового процесса.** Для MediaPipe в готовой игре используем отдельный упакованный процесс, а для правил боя — C++/Blueprints. [Ограничения Python в Unreal](https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python).

## 3. Дать агентам реальные файлы и инструменты

Открой проект в Codex на Windows, если приложение доступно в твоей конфигурации, либо используй доступный локальный клиент Codex. Для Claude установи Claude Code по официальной инструкции и запусти его из корня проекта. Выбери Opus 5.5 через доступный выбор модели. [Официальная установка Claude Code](https://code.claude.com/docs/en/setup).

Обоим агентам дай большой промт и план разделения ролей. Opus дополнительно получает `prompt-for-opus.md`, Codex — `prompt-for-codex.md`.

Первое задание агенту на Windows: определить реальные пути UnrealEditor.exe, UnrealEditor-Cmd.exe и Blender.exe, проверить проект и выполнить probe. Доступ к терминалу и папке нужен фактически, а не только в виде прикреплённого документа.

Для обычного запуска редактора из PowerShell можно использовать такой шаблон:

```powershell
# Пример: подставить найденную версию UE и реальные пути.
$IronEchoEditor = 'C:\Program Files\Epic Games\UE_5_X\Engine\Binaries\Win64\UnrealEditor.exe'
$IronEchoProject = 'D:\Games\IronEcho\Game\IronEcho.uproject'
if (-not (Test-Path -LiteralPath $IronEchoEditor)) { throw 'Проверь путь UnrealEditor.exe' }
if (-not (Test-Path -LiteralPath $IronEchoProject)) { throw 'Проверь путь .uproject' }
& $IronEchoEditor $IronEchoProject
```

`UE_5_X` — пример, его нельзя оставлять как настоящий путь. Не запускай второй редактор на эту же рабочую копию, если она уже открыта.

Редакторские скрипты также можно запускать пакетно через официальные command-line режимы. Opus должен выбрать режим, подходящий скрипту: некоторые операции требуют загрузки уровня. Повторный процесс не должен писать в ассеты одновременно с открытым редактором. [Режимы запуска Epic](https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python).

## 4. Подключить Blender

Проверь установленный Blender и запуск пустой сцены. Codex создаёт скрипты в `Tools\Blender`, исходники в `ArtSource`, экспортные файлы в отдельном рабочем каталоге.

Запуск скрипта внутри Blender: рабочая область **Scripting**, открыть нужный файл, выполнить **Run Script**. Для повторяемых экспортов можно использовать командную строку после проверки параметров установленной версии. Не запускай неизвестный генератор поверх важной открытой сцены.

Перед первым импортом согласуйте единицы, scale, ориентацию, имена костей и сокетов. Само наличие .blend не означает корректный импорт скелета в Unreal.

Codex подготавливает ассет и editor-скрипт импорта. Opus обеспечивает технический проект и проверяет интеграцию. Не нужно требовать ручного клика по каждой детали модели, если операцию можно воспроизводимо выполнить скриптом.

## 5. Нужен ли Unreal MCP

Для начала — нет. Надёжная исходная схема: локальные файлы, терминал, официальная редакторская автоматизация и логи. Она не зависит от неизвестного стороннего моста.

Если позже потребуется интерактивное управление открытым редактором, выбирайте мост после проверки поддержки установленной версии UE, доступных операций и границ доступа. Подключение MCP к одному агенту не подключает автоматически второй клиент.

Не открывайте удалённое выполнение команд на все сетевые интерфейсы ради удобства. Локальному агенту хватает localhost или пакетных скриптов. Для удалённой машины потребуется отдельная контролируемая схема доступа; этот документ её не устанавливает.

## 6. Как работать вдвоём без конфликтов

- Opus создаёт проект, gameplay, трекинг и общие контракты.
- Codex создаёт графику, сцену, анимацию, визуальные компоненты и UMG.
- Бинарные карты и ассеты имеют одного владельца на запись.
- Перед импортом или интеграцией второй агент закрывает редактор своей рабочей копии.
- Передача идёт через commit и отчёт с путями, версией контракта и результатом проверки.
- При двух рабочих копиях интегратор переносит согласованные изменения и запускает полный бой.

Не заставляйте два ИИ одновременно редактировать один Blueprint, .umap или .blend. На RTX 3050 также разумно выполнять тяжёлый Blender-рендер и игровые замеры по очереди.

## Когда подключение действительно готово

1. Проект Unreal открывается и базовый C++ target собирается.
2. Probe выдаёт сообщения в Output Log.
3. Агент читает и меняет разрешённые файлы проекта через реально доступные инструменты.
4. Blender выполняет воспроизводимый графический скрипт.
5. Тестовый ассет импортирован в Unreal и виден в уровне.
6. Отдельный MediaPipe-процесс передаёт данные, которые Unreal действительно получает.
7. Изменение позы человека вызывает наблюдаемое движение тестового робота.

Пункты 1–4 проверяют инструменты, 5 — графический pipeline, 6–7 — игровой ввод. Пока они не выполнены, не называйте систему полностью подключённой.

Источники проверены 2 октября 2026 года. Установленные версии и доступность клиента нужно подтвердить на конкретном Windows-ПК.
