# IRON ECHO — визуальный фундамент UMG

Статус: **исходники и макеты подготовлены; добавлен C++-черновик native menu/HUD в IntegrationDraft/IronEchoVisuals 0.2-draft, но UE сборка/поведение не проверены**. Эта спецификация также описывает будущие экраны калибровки/настроек/паузы/результатов, которых в черновике пока нет.
Версия пакета: `codex-ui-0.1`. Принятый игровой контракт Opus отсутствует.
Схемы JSON этого пакета относятся к художественным исходникам, а не заменяют контракт игрового состояния.
Применены доступные правила `ui-ux-pro-max`: контраст, фокус, SVG, площадь управления, видимые подписи и уменьшение движения. Веб-стек не используется.

## Визуальный язык

Промышленный графит, тёплый янтарь для основного действия и бойца игрока, холодный циан для противника и вторичных информационных акцентов. Жёсткая сетка, небольшой радиус углов, короткие подписи. Нет неоновых градиентов, размытия панели во весь экран и светящихся тонких шрифтов.

`ArtSource/UI/theme.json` — единственное место цветовых литералов. Во всех новых виджетах использовать ссылки на семантические значения:

| Применение | Токен |
| --- | --- |
| Фон экрана / непрозрачная подложка HUD | `background` / `surface` |
| Поднятая панель / дорожка индикатора | `surfaceRaised` |
| Основной / вторичный текст | `text` / `textMuted` |
| Основное действие / его подпись | `primary` / `onPrimary` |
| Фокус клавиатуры и геймпада | `focus` |
| Граница управления | `outline` |
| Неактивное управление | `disabledSurface` / `disabledText` |
| Готовность / предупреждение / ошибка | `success` / `warning` / `error` |
| Целостность игрока / противника | `healthPlayer` / `healthOpponent` |
| Выносливость | `stamina` |

Панели под текстом HUD непрозрачны. Контраст нельзя гарантировать на произвольном изображении арены, поэтому текст не размещать прямо на видео или сцене без подложки. Оттенок не заменяет подпись: «Управление активно», «Кисти плохо видны», «Игрок вне кадра» имеют также разные иконки.

Источник `ui_text.ru.json` содержит начальную русскую копию; Opus импортирует её в согласованную локализацию проекта. Не поддерживать отдельную конкурирующую систему локализации в визуальном плагине. Шрифт проверить на всех кириллических буквах, цифрах и символе многоточия. В пакете нет файлов шрифтов. Для меню нужен читаемый гротеск, для таймера — цифры одинаковой ширины, если выбранный шрифт это позволяет.

## Общие виджеты и владение

Предлагаемые пути после регистрации визуального плагина: `Game/Content/Art/UI/Widgets`, `…/Theme`, `…/Icons`, `…/Fonts`. Это будущие импортные пути; `.uasset` сейчас не созданы.

| Виджет | Содержание |
| --- | --- |
| `WBP_IEButton` | Контейнер не менее 48×48 логических единиц; Label; необязательная Icon; отдельная FocusOutline; состояния Normal, Hover, Pressed, Focused, Disabled |
| `WBP_IEField` | Постоянная видимая подпись над контролом; helper text; ошибка непосредственно под ним |
| `WBP_IEScreenRoot` | Safe Zone → Overlay → адаптивный контейнер; текущий экран; слой ошибок и modal layer |
| `WBP_IEMainMenu` | Логотип-текст, требование камеры, вертикальная группа действий, место фоновой сцены |
| `WBP_IECalibration` | Локальный предпросмотр, явный выбор камеры, инструкции, состояние проверки и один основной переход |
| `WBP_IEHUD` | Два FighterStatus, RoundClock, TrackingStatus, Pause control |
| `WBP_IEPause` | Продолжить, камера, настройки, завершить бой |
| `WBP_IESettings` | Качество, масштаб UI, уменьшение движения, тряска, звук/субтитры; согласованный набор Opus |
| `WBP_IEResult` | Результат и причина из игры; ещё один бой, главное меню |

Создание виджета происходит после принятия интерфейса данных. Пакет даёт структуру и исходники, не объявляет перечисленные классы уже существующими.

Сборка визуального слоя читает состояние из источника Opus. Нельзя вычислять урон, победу, фазу раунда, успех калибровки, готовность камеры или расход выносливости в UI. Отображаемое поле не становится отдельной игровой системой. HUD держит только последний снимок для отображения и освобождает подписку при закрытии.

## Данные, которые нужны от Opus

Список ниже — запрос к контракту, **не зафиксированный wire-format и не новая версия ROBOT_VISUAL_CONTRACT**.

| Снимок / событие | Требуемые визуальные данные |
| --- | --- |
| Боец | Отображаемое имя; текущее/максимальное здоровье и выносливость; идентификатор стороны; доступность данных |
| Матч | Состояние матча; номер/число раундов; авторитетное оставшееся время; результат и причина остановки |
| Камера | Список разрешённых устройств и понятные названия; выбранное устройство; Open/Busy/Missing/PermissionDenied/Failed; предпросмотр или отсутствие кадра |
| Трекинг | Stable/Degraded/Lost/Recovering; достаточность позы для текущего шага; причина остановки из игры |
| Калибровка | Текущий шаг, инструкция, состояние готовности, подтверждённый успех/ошибка; реальный прогресс, если он есть |
| Настройки | Принятые значения, dirty draft, допустимые диапазоны и ответ сохранения/ошибки |
| Статус загрузки | Реальная фаза и готовность; процент только при измеряемом полном объёме работы |

Команды, которые нужны визуальному слою: выбор камеры, запуск/повтор калибровки, скрытие предпросмотра, старт локального матча, пауза/возобновление, завершение матча, сохранение настроек и выход. Названия команд определяет Opus. Успех отображать после подтверждения, ошибку — возле инициировавшего контрола. Повторное нажатие не должно создавать два запроса или два матча.

Авторитетная пауза при потере трекинга относится к gameplay. UI показывает «Бой приостановлен» только когда игра подтвердила эту паузу; иначе — «Игрок вне кадра» и инструкцию восстановления. Автоматическая пауза не запускается локальной логикой HUD.

Не показывать обещание локальной обработки и выключенной записи, пока интегратор не подтвердит эти режимы. `camera.privacy` отображается только из подтверждённого camera service state. Макетная копия показывает желаемое поведение, а не проведённую проверку устройства.

## Главное меню

Два честных варианта:

1. Камера ещё не настроена: основное действие «Настроить камеру»; «Начать бой» неактивно с понятным объяснением. Не скрывать требование камеры.
2. Камера и калибровка готовы: основное действие «Начать бой»; настройка камеры вторична.

«Настройки» и «Выход» вторичны. Не показывать сетевые комнаты, рейтинг или магазин. Фоновая сцена может использовать робота в стойке в недорогом статичном ракурсе; снижать её детализацию отдельно от боя. Уменьшение движения отключает декоративное покачивание и переход камеры. Сцена не отнимает фокус у кнопок.

После возврата из настроек фокус возвращается на «Настройки». После успешной калибровки — на «Начать бой». Первое открытие без готовой камеры ставит фокус на «Настроить камеру». Без подключения камеры кнопка не должна сообщать, что бой доступен.

## Камера и калибровка

Общая компоновка: крупный предпросмотр с рамкой кадра, рядом короткие инструкции; под кадром поле «Камера» и переключатель предпросмотра; нижняя строка одного основного действия и вторичной кнопки «Назад».

Предлагаемые этапы согласовать с Opus: выбор камеры → положение тела и защитная стойка → пробные движения. Шаг считается завершённым по данным трекинга. Вторая камера отсутствует в первой версии.

| Состояние | Видимый результат |
| --- | --- |
| Поиск >300 мс | Неподвижная skeleton-подложка списка устройств и «Ищем доступные камеры…»; без выдуманного процента |
| Устройства нет | Ошибка под полем, инструкция подключения, единственная primary «Повторить поиск» |
| Устройство занято | Краткое объяснение и способ закрыть использующее приложение; подробный код только в диагностике |
| Доступ запрещён | «Проверьте доступ в настройках Windows»; никаких имён библиотек или стека ошибок |
| Кисти/таз не видны | Текстовая инструкция и понятная контурная подсказка; нельзя использовать только цвет |
| Проверка стойки | Инструкция из текущего шага; действие не принимает повторный запуск; Escape остаётся доступным |
| Успех | «Калибровка завершена» и primary «Перейти к бою»; «Повторить калибровку» вторично |
| Предпросмотр скрыт | Непрозрачная панель «Предпросмотр скрыт»; трекинг продолжает работу по режиму Opus |

Лицо и видеокадр не сохраняются UI. Выбор диагнoстической записи отсутствует в основном потоке; если Opus реализует запись координат, нужен отдельный ясный экран с согласованным описанием и выключенным по умолчанию переключателем.

## HUD боя

Верхний левый угол — игрок, верхний правый — противник; по центру номер раунда и время. Подписанные показатели «Целостность» и «Выносливость» используют значения `current / maximum` из игры, а не всегда фиксированное `/100`. Пример в SVG использует условные числа только для компоновки.

Не перекрывать голову, перчатки и плечи противника из основной камеры. Центральные 60% ширины и 55% высоты остаются без постоянных виджетов; критерий проверить с реальным ракурсом и на крайних позициях обоих бойцов. Пауза — нижний левый угол, статус трекинга — нижний правый, непрозрачная компактная панель. Камерный предпросмотр в бою по умолчанию скрыт и не является обязательным HUD.

Ресурсы обновляются от события состояния, таймер — от авторитетного снимка. Виджет не ведёт собственный отсчёт матча. Обновление FillPercent индикатора отражает полученное значение; нет анимации width/height, отдельной симуляции ресурса, пульсации низкого здоровья или скрытого приращения урона. При неизвестных данных — «—» и недоступное состояние вместо фиктивного нуля.

Не подписываться к позе на каждом кадре ради HUD; агрегированный tracking status обновляется от Opus. Уменьшение движения убирает рывки уведомлений, тряску UI и декоративные вспышки. Разрешены статичный текст, изменение смыслового значения и дискретная смена иконки.

## Пауза, настройки и результат

Пауза появляется только после подтверждения игры, затем фокус на «Продолжить». Камера и настройки открываются вторичными действиями. Если трекинг всё ещё потерян и игра не разрешает продолжить, primary становится «Проверить камеру», а «Продолжить» неактивно с объяснением.

«Завершить бой» открывает компактное подтверждение с primary «Завершить бой» и вторичной «Вернуться». Это прерывает текущий матч; нельзя случайно завершить его тем же нажатием, которое открыло диалог. Escape закрывает диалог, а не завершает бой.

Настройки — прокручиваемая вертикальная форма с видимыми labels. Каждый slider содержит число и кнопки уменьшить/увеличить; клавиатура и геймпад работают без мыши. «Уменьшение движения» сразу убирает декоративную анимацию; тряска камеры также имеет отдельный диапазон с нулём. «Применить» — primary при несохранённых изменениях; остальные переходы вторичны. Только settings service Opus сохраняет значения. Ошибка сохранения не сообщает «Настройки сохранены».

Результат принимает Winner/Reason от gameplay. Никаких локальных предположений из health bar. Primary «Ещё один бой», вторично «В главное меню». Режим реванша проходит проверку актуальности камеры и калибровки через Opus. Кинематографический повтор можно пропустить отдельным вторичным управлением с явной подписью.

## Фокус, доступность и масштаб

- Все интерактивные элементы видимо подсвечены обводкой `focus` толщиной 3 логические единицы. Hover и keyboard focus различаются; disabled нельзя спутать с отсутствием фокуса.
- Порядок Tab и направлений геймпада следует чтению сверху вниз и слева направо. Dropdown и modal удерживают фокус только пока открыты, затем возвращают его инициатору. Не позволять HUD ловить боевой ввод во время активного матча.
- Область нажатия кнопок не менее 48×48 логических единиц, зазор ≥8; minimum requirement пользователя 44. Проверить **фактический** размер после UMG DPI scale, чтобы уменьшение масштаба не дало цель меньше 44 экранных пикселей в узкой тестовой конфигурации.
- Подписи полей видимы постоянно; ошибка непосредственно под полем. Не использовать один placeholder вместо label.
- Иконки — исходные SVG `ArtSource/UI/Icons`. SVG импортер не предполагается установленным: согласовать импорт либо экспортировать в PNG на прозрачном фоне на 1×/2× перед UMG. Прозрачность у иконок нужна, у подложек HUD — нет.
- Для значимого графического контента задать человекочитаемое доступное имя средствами выбранной версии UMG/Slate. Декоративный фон и дублирующая иконка не должны объявляться дважды. Screen reader поведение нужно отдельно проверить на Windows, оно не доказано наличием SVG `<title>`.
- Основной текст 18, нижний предел пояснения 16 логических единиц. Масштаб UI 100/125/150% должен оставлять кнопки и ошибки доступными; узкий макет допускает вертикальную прокрутку, горизонтальную — нет.
- Субтитры и статусы размещаются вне зоны атак. Низкое качество трекинга сопровождается текстом, а не одним жёлтым индикатором.

### Адаптивные ограничения

Это проверки читаемости и UMG компоновки, **не обещание мобильного релиза**. Нет телефона как целевой игровой платформы.

| Доступная ширина | Решение |
| --- | --- |
| 375 | Меню в одну колонку, отступ 16, без декоративной 3D-вставки. Калибровка: preview сверху, инструкции/контролы ниже в вертикальном ScrollBox. HUD: компактные подписанные значения, tracking banner внизу по ширине, central fighting area свободна |
| 768 | Одна колонка меню до 440 шириной; preview и инструкции калибровки вертикально; HUD две симметричные панели с таймером между/над ними по фактической доступной ширине |
| 1024 | Меню + сцена справа; калибровка в две колонки только если поля сохраняют ≥320 ширины; HUD два corner panels и central timer |
| 1440 и выше | Основной desktop вариант; важные controls не растягиваются во всю ширину; контент на Safe Zone, HUD привязан к углам |

Использовать адаптивные контейнеры, а не единственный растянутый Canvas на 1920×1080. Настройку глобальной DPI curve в `Config` делает Opus; визуальный слой передаёт требования, но не переписывает его Config. При ultrawide HUD остаётся внутри согласованной игровой safe area и не прячет статусы на краях. Нижняя высота 720 и UI scale150% проверяются отдельно.

## Анимации UMG

Motion tokens в `theme.json`: вход 240 мс, выход 96 мс — на 60% короче входа, нажатие 160 мс, stagger40 мс. Изменять только Render Transform и Render Opacity; layout properties не анимировать. Вход — ease-out, выход — ease-in. Пользовательский ввод прерывает переход и ставит виджет в корректное конечное состояние.

`reducedMotion` отключает translate/scale и анимацию времени, оставляя статичное переключение состояния. Учитывать настройку игры, а системную настройку — если выбранный Windows/Unreal adapter её предоставляет; не заявлять, что `prefers-reduced-motion` браузера применён к UMG. При отключённой анимации фокус появляется немедленно. Ни один переход не задерживает паузу, начало восстановления камеры или кнопку пропуска выхода бойцов.

## Импорт и проверка на целевом ПК

1. Opus предоставляет принятые интерфейсы UI data/commands, локализацию и подтверждает регистрацию IronEchoVisuals.
2. Codex создаёт Theme Data Asset или аналогичный единый ресурс токенов из JSON. Значения JSON — sRGB; при преобразовании к linear color не применять гамму дважды. В редакторе сверить фактические цвета и кадр вывода.
3. Импортировать SVG через проверенный поддерживаемый путь либо прозрачные PNG; собрать общий button/field, затем menu/calibration/HUD. У каждого `.uasset` один автор на время записи.
4. Opus подключает read-only snapshots и command adapter. Художественные виджеты не импортируют Tracking Python и не обращаются к камере сами.
5. Проверить отсутствие камеры, Busy, PermissionDenied, Lost, Recovering и успешный матч. В каждом случае copy соответствует настоящему состоянию.
6. Проверить весь путь только клавиатурой, затем геймпадом; Tab, Enter/Space, Escape/Back, возврат фокуса, disabled controls и смену устройства ввода.
7. На 375/768/1024/1440, 1920×1080 и ultrawide проверить отсутствие обрезания, размер target, 100/125/150% UI scale, длинное имя камеры/бойца и кириллицу.
8. По финальным кадрам из упакованной Windows-сборки перепроверить текстовый контраст минимум 4.5:1, фокус/границы минимум3:1 и непрозрачность HUD. JSON ratios не доказывают итоговую гамму/tonemapping.
9. Включить уменьшение движения и нулевую тряску: переходы мгновенны, нет декоративного движения и пульсации. Проверить ошибки калибровки и возможность всегда выйти.
10. Измерить UMG/Slate CPU/GPU cost с боями и камерой. Нет Tick binding на всех текстах, тяжёлого Background Blur и постоянного скрытого full-resolution preview. Бюджет UI — целевой ориентир до1 мс CPU и до1 мс GPU на RTX3050, подтвердить профилем; это не полученное измерение.

## Проведённая проверка источников
