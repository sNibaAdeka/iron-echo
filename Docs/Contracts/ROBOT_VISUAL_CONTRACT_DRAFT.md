# ROBOT_VISUAL_CONTRACT — предложение Codex

Идентификатор: `IE-VIS-DRAFT-0.1`. Статус: **DRAFT / FOR OPUS REVIEW**. Дата: 2026-10-02.

Принятый `ROBOT_VISUAL_CONTRACT.md` Opus в доступных файлах отсутствует. Этот документ фиксирует подготовленную визуальную геометрию и предлагает интерфейс интеграции; он не является утверждённым gameplay-контрактом. Исходный формат позы, команды трекинга и архитектуру проекта определяет Opus. Codex не создаёт второй протокол MediaPipe.

## Владение

Codex владеет ArtSource, генераторами Blender, импортёром Art, визуальными материалами и проверками ассетов. Opus владеет проектом, gameplay, входной позой, авторитетными контактами, настройками и сборками. `IronEchoVisuals` подключается только после регистрации и согласования интегратором; настоящего runtime-модуля этот черновик не создаёт.

Повреждения, коллизии боевых объектов, выбор цели и активная фаза атаки принадлежат Opus. Ни сокет, ни анимационная метка, ни Niagara/UMG не рассчитывают урон. Файл принятого контракта записывает назначенный автор после проверки настоящего импорта.

## Система координат и масштаб

| Поле | Подготовленный источник / требование при импорте |
|---|---|
| Blender | Метрические координаты: 1.0 единица = 1 м |
| Оси исходной модели | +Z вверх, −Y вперёд, +X направо для робота |
| Высота | Около 2.15 м; точное значение берётся из отчёта экспортированной сетки |
| Положение источника | Стопы у Z=0, центр рига у X=Y=0; transforms объекта применены перед экспортом |
| FBX | Forward −Y, Up Z; apply unit scale по экспортному скрипту |
| Unreal | 1 единица = 1 см; целевая ориентация +X вперёд, +Z вверх |
| Root motion | Не запекается; перемещение игрового Actor принадлежит Opus |

`Force Front X Axis` или эквивалентное преобразование при FBX-импорте является кандидатом настройки. Сам факт задания флага не подтверждает правильный поворот. В Unreal нужно измерить высоту около 215 см и визуально/программно проверить лицевую сторону, кулаки, оси костей и отсутствие двойного пересчёта единиц. Если проверка не проходит, корректируется один экспортный/импортный путь и публикуется новая версия черновика.

## Общая иерархия костей

Имена и родительство подготовлены для обоих роботов. Кости не переименовывать автоматически при импортировании второго облика.

```text
root
└── pelvis
    ├── spine_01
    │   └── chest
    │       ├── neck
    │       │   └── head
    │       ├── clavicle_l
    │       │   └── upperarm_l
    │       │       └── lowerarm_l
    │       │           └── hand_l
    │       └── clavicle_r
    │           └── upperarm_r
    │               └── lowerarm_r
    │                   └── hand_r
    ├── thigh_l
    │   └── calf_l
    │       └── foot_l
    └── thigh_r
        └── calf_r
            └── foot_r
```

В списке 20 костей. Точные rest transforms определяются генератором и отчётом рига. Этот скелет не объявляется совместимым с Epic Mannequin/MetaHuman. Add Leaf Bones отключён. Один Skeleton в Unreal допустим только после сравнения всех rest transforms и parent indices; совпадения названий недостаточно.

Каждая жёсткая панель привязана к одной кости с весом 1.0. Не добавлять сглаженные веса металлическим деталям. Проверка экспорта должна обнаруживать вершины без веса, несколько влияний и отсутствующую кость. Две ливреи могут различаться шириной внешних панелей, но не положением суставов.

## Материальные слоты

Порядок: `Gunmetal`, `Armor`, `Brass`, `Rubber`, `Signal`. Геометрия и генератор сохраняют этот порядок. Импортёр создаёт или назначает материалы из `/Game/Art/Materials`; изменения оттенка по бойцам выполняются инстансами.

Готовность UV, нормалей, tangents и сопоставления шейдеров требуется проверять в import report. Наличие цветного материала в Blender не означает, что материал готов для игры. Основной FBX переносит геометрию и риг; финальный Unreal lookdev принадлежит отдельному шагу.

## Сокеты: предложение, требующее проверки

| Сокет | Кость | Начальное смещение | Применение |
|---|---|---|---|
| `Fist_L` | `hand_l` | translation/rotation 0, scale 1 | Опорная точка левого кулака |
| `Fist_R` | `hand_r` | translation/rotation 0, scale 1 | Опорная точка правого кулака |

Нулевая позиция — временная договорённость. Центр кулака для swept contact может находиться вне начала кости; Opus должен проверить соответствие contact radius, головы/корпуса цели и траектории импортированной анимации. До этого сокеты непригодны как доказательство корректного попадания. Точки локтя/кисти для IK используют кости, а не новые имена сокетов без версии контракта.

## Анимационные ассеты

Основной robot FBX экспортируется без анимаций. Каждая action экспортируется отдельным FBX с тем же ригом, без leaf bones, без baked root motion. FPS и число кадров фиксируются в фактическом отчёте генератора. Названия ниже — семантика действий, точные пути файлов указаны в manifest пакета.

| Действие | Тип | Предложение визуального поведения | Владелец разрешения/прерывания |
|---|---|---|---|
| `Idle` | Loop | Небольшое дыхание механизма и стабильные стопы | Opus выбирает при отсутствии action |
| `Guard` | Hold/loop | Обе руки защищают верхний корпус | Opus определяет активность блока |
| `Straight_L` | One-shot | Подготовка, вылет левого кулака, возврат | Opus: начало, active, recovery, hit/KO interrupt |
| `Straight_R` | One-shot | Подготовка, вылет правого кулака, возврат | Opus: начало, active, recovery, hit/KO interrupt |
| `Dodge_L` | One-shot | Смещение корпуса и головы влево, возврат | Opus: разрешение уклона и выход |
| `Dodge_R` | One-shot | Смещение корпуса и головы вправо, возврат | Opus: разрешение уклона и выход |
| `HitReact` | One-shot | Краткая реакция корпуса на подтверждённый контакт | Opus: контакт/статус, правила прерывания |
| `KO` | One-shot / terminal | Падение или отключение механизма, завершение | Opus: knockout и результат матча |

Черновой прямой удар: полная длина 0.50 с; подготовка 0.00–0.16 с, предполагаемое визуальное выдвижение 0.16–0.24 с, возврат 0.24–0.50 с. В нормализованном времени это 0–0.32, 0.32–0.48, 0.48–1.0. **Это предложение для согласования, а не действующий интервал урона.**

Интеграция должна получать от gameplay начало action, длительность и активную фазу, затем масштабировать визуальное проигрывание. При принятии других таймингов Opus/Codex проверяют скорость кулака и сохраняют новое согласованное значение. AnimNotify допускается для визуального звука/служебной диагностики, но не создаёт авторитетный контакт.

## Предложение входов визуального слоя

Имена в таблице иллюстрируют потребности слоя и не объявляют готовый C++/Blueprint API. Конечный интерфейс и пространство координат позы предоставляет Opus.

| Потребность | Смысл |
|---|---|
| Снимок позы | Уже обработанные Opus targets/rotation, confidence и возраст; визуальный слой не повторяет распознавание |
| Состояние action | Имя, левая/правая сторона, start time, duration, normalized phase, допустимые переходы |
| Состояние защиты/уклона | Согласованный blend и игровой статус; не выводится из косметической анимации |
| Статус трекинга | valid, stale/lost, paused; достоверность определяет Opus |
| Контакт | Уникальный event id, участники, world position/normal, тип контакта, visual intensity |
| Состояние матча/HUD | Read-only здоровье, выносливость, раунд, время, результат и статус ввода |
| Настройки | От Opus: reduced motion, интенсивность shake, масштаб UI, качество и настройки камеры |

При недостоверной позе визуальный слой затухает к согласованной стойке без запуска новых ударов. Возможность продолжить бой или поставить его на паузу определяет gameplay. Старое pose sample не вызывает новую атаку после восстановления.

## Слои анимации и VFX

Предложенный порядок: базовая стабильная стойка → обработанная поза/ограниченный IK → action override руки и корпуса → подтверждённая hit reaction. KO имеет высший приоритет после авторитетного сообщения. Ограничения суставов и веса слоёв проверяются на imported rig; готового Anim Blueprint/Control Rig пока нет.

VFX принимает подтверждённый контакт от Opus. Один event id испускает эффект один раз. Удары по воздуху, неавторитетный overlap и задержанная повторная доставка не создают искры или повреждение. CosmeticDamage меняет визуальные параметры только по игровой команде; отдельное визуальное здоровье запрещено.

## Порядок принятия

1. Opus создаёт настоящий Unreal-проект и передаёт свою версию позы, действий, настроек и событий контакта.
2. Codex и Opus сравнивают skeleton, transforms, материал/сокеты и оси после импортирования одного робота и одной straight animation.
3. Проверяют траекторию кулака, active interval и блок на тестовой цели; переходы pose/action не дают скачка запястья.
4. Один назначенный автор выпускает принятый `ROBOT_VISUAL_CONTRACT.md` с версией, владельцами и конкретными путями.
5. Codex обновляет генераторы/импортёр при отличиях; отчёт передачи указывает новую версию и необходимость повторного импорта.

Открытые пункты: реальная версия UE/FBX pipeline, VRAM RTX 3050, измеренный unit conversion, skeleton asset path, bone rest transforms в Unreal, contact radius/offset, API позы, сроки/разрешения action, runtime-подключение камеры/VFX/UI, профилирование packaged build.
