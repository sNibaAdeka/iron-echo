# Продолжение IRON ECHO на Windows

Этот файл нужен агенту на компьютере с RTX 3050, где уже установлен Unreal Engine. Базовый graphics-пакет переносится через GitHub; игру не нужно придумывать заново.

## Получить файлы

Авторизуй GitHub на самом Windows-ПК. Для приватного репозитория используйте аккаунт владельца. При установленном GitHub CLI:

```powershell
gh auth login
gh repo clone sNibaAdeka/iron-echo
cd iron-echo
```

Либо клонируй URL через обычный Git с настроенной авторизацией. Не присылай токены в чат.

## Сообщение для продолжения этого чата

Подставь фактический путь к клонированной папке:

> Я на Windows-ПК с RTX 3050. Проект клонирован в C:\путь\iron-echo. Прочитай AGENTS.md, PROJECT_STATE.md и WINDOWS_START.md. Продолжай графическую часть с последнего результата. Проверь установленный Unreal и запусти импорт подготовленных роботов и тестовой арены. Не меняй технические файлы Opus без согласования.

Само открытие того же чата на другом компьютере не копирует локальные файлы старого компьютера. Источником проекта является этот репозиторий и указанный локальный путь.

## Первое задание Opus

Дай ему Docs/Briefs/prompt-for-opus.md. Он проверяет или создаёт Unreal C++-проект в Game, компилятор и плагины. Точные версии и пути должны быть найдены на Windows, а не скопированы с Mac.

До графических операций сохранить текущий уровень и остановить Play In Editor. Первая проверка — Tools/Unreal/Art/ue_connection_probe.py. Затем — run_art_setup.py через File → Execute Python Script.

Ожидаемая sandbox-карта: /Game/Art/IronEcho/Arena/L_IE_ArtSandbox. Отчёты запуска — Saved/IronEchoArtReports. Отсутствие ошибок нужно подтверждать этими отчётами и просмотром моделей/анимаций, а не ожиданием по инструкции.

## Если импорт завершился ошибкой

Сохрани точный traceback и версию Unreal. Скрипты ориентированы на классический Python FBX API 5.6; новая версия движка может требовать адаптации. Не перезаписывай материалы/карты другого автора и не отключай проверки только ради продолжения.

После подтверждённого импорта продолжай согласование контракта и подключение gameplay. Опубликованные в репозитории 50 Blender-проверок не означают подтверждённую работу игры на Windows.

## Следующий графический этап

Прочитай Docs/Handoffs/Codex/runtime-visuals.md и IntegrationDraft/IronEchoVisuals/README.md. В репозитории уже подготовлены C++-исходники UMG меню/HUD, камеры и косметических искр. После принятия presentation adapter Opus переносит плагин в Game/Plugins, включает его в своём проекте и выполняет полную Development Editor Win64 сборку. Здесь нет готовых бинарников: первое подключение требует настоящей компиляции и проверки UHT. При её ошибках сохранять точную диагностику и исправлять код под фактическую версию UE.

Unreal стоит подключать после первого робота, не ждать окончания всей игры: импорт, материалы, скелет и движения проверяются именно в движке. На целевом Windows Unreal уже установлен по сообщению владельца; его версию ещё нужно определить.
