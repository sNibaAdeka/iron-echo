# IronEchoVisuals — исходники 0.2-draft

Это подготовленный C++ runtime-плагин для Unreal, ещё **не скомпилированный и не подключённый**. На машине подготовки Unreal нет. Код хранится отдельно от Game/Plugins, чтобы Opus принял интерфейс и зарегистрировал модуль в своём проекте. Файлы .uproject, Config и gameplay не изменялись.

Интерфейс представления: `IE-PRESENT-DRAFT-0.1`. Он дополняет `IE-VIS-DRAFT-0.1` для ассетов и не заменяет протокол входной позы MediaPipe. Принятого контракта пока нет.

## Состав

| Класс | Назначение |
|---|---|
| UIEMenuWidget | Русское меню: одна основная кнопка, камера, настройки, выход; команды через OnActionRequested |
| UIEHUDWidget | Отображение переданного снимка боя, здоровья/выносливости/раунда/таймера и состояния трекинга |
| AIEVisualCameraRig | Камера из-за плеча с SpringArm, проверкой препятствий и короткой реакцией на подтверждённый контакт |
| AIEImpactVisualActor | Ограниченный пул из 48 косметических искр, 2–8 на событие, без игровых коллизий и урона |
| IETheme.h | Цвета и метрики, воспроизводимо сгенерированные из ArtSource/UI/theme.json |

Native widgets строят свой WidgetTree до создания Slate-виджетов. Они владеют компоновкой: Designer tree в Blueprint-потомке будет заменён. В первой интеграции создавай именно нативные классы через CreateWidget и не добавляй параллельную систему UI.

## Подключение — задача Opus на Windows

1. Прочитай `Docs/Handoffs/Codex/runtime-visuals.md`, согласуй адаптер команд/данных и версию контрактов. Проверь реальную версию UE и C++ toolchain.
2. При закрытом редакторе скопируй эту папку в `Game/Plugins/IronEchoVisuals`. Не перезаписывай существующий плагин другого автора.
3. Зарегистрируй/включи `IronEchoVisuals` в проекте. EnabledByDefault=false намеренно. Добавь зависимость `IronEchoVisuals` в модуль интеграции, если его C++ использует эти классы; за .uproject/Build.cs игрового проекта отвечает Opus.
4. Перегенерируй проектные файлы подходящим для установленного UE способом и выполни полную сборку `Development Editor / Win64`. Первое создание UCLASS/USTRUCT требует проверки UHT; наличие файлов не подтверждает сборку. Не подменяй её попыткой Hot Reload.
5. Исправь реальные диагностические ошибки компилятора под установленную версию, сохрани лог. Затем запусти редактор и sandbox.
6. Создай виджеты с OwningPlayer, сначала AddToViewport, потом передавай данные. Ввод UIOnly/GameAndUI, видимость курсора, пауза и возврат GameOnly остаются в PlayerController Opus. После установки режима ввода вызови меню FocusPrimaryAction(), чтобы начальный фокус попал на основную кнопку уже в подключённой Slate-иерархии.

## Меню и HUD

`OnActionRequested` только сообщает запрос: StartMatch, OpenCalibration, OpenSettings, ExitRequested, CloseRequested. Здесь нет запуска камеры, калибровки, изменения настроек или выхода из приложения. Opus связывает каждый запрос с существующей командой. `SetCameraReady(true)` вызывается только после реальной готовности трекинга и калибровки. `ShowCameraMessage` выводит фактическое состояние.

Меню использует кнопки высотой 56 логических единиц, видимую рамку фокуса, Tab/Shift+Tab/стрелки, Enter/Space через кнопку и Escape как запрос закрытия. Цвета идут из единой темы. Появление изменяет только opacity за 240 мс. `SetReducedMotion(true)` делает его мгновенным. Настройки/калибровка/пауза/экран результатов пока не реализованы; экран меню даёт команды для следующего этапа.

`ApplySnapshot(FIEHUDSnapshot)` вызывается из событий изменения авторитетных данных и обновления таймера. Не вычисляй внутри адаптера отдельные здоровье/урон/выносливость. Значения Current/Max должны быть конечными, Max>0, Current в пределах 0..Max; раунд 1..TotalRounds, TotalRounds≤99; таймер в пределах 0..86400 секунд. При отсутствии/ошибке данных виджет скрыт и возвращает false. Таймер только форматирует число, самостоятельно не отсчитывает время. `ClearSnapshot()` нужен при завершении/разрыве подписки. Обработка false и согласование enum трекинга — ответственность адаптера. Тексты имён приходят извне; длинные имена и DPI нужно проверить в UE.

## Камера

Создай AIEVisualCameraRig, передай настоящих акторов в `FollowRobot(Player, Opponent)`, активируй через PlayerController `SetViewTargetWithBlend`. FollowOffset/OpponentAimOffset относительно transform соответствующего актора. Значения по умолчанию предполагают pivot у ног; для capsule-персонажа их нужно поправить под реальный pivot. SpringArm — 320 см, плечо +65 см, FOV 75. Проверку Camera collision объектов арены настрой и проверь в интеграции.

Камера не меняет дистанцию боя, положение бойца, цель атаки или игровую позу. Нет выхода бойцов/Sequencer. `ApplyConfirmedContactKick` вызывается только на одном подтверждённом контакте; повторение сетевого события должен исключать адаптер. Reduced motion отключает контактную тряску, следование остаётся. Эти численные настройки — стартовые, читаемость атаки и обрезание геометрии ещё не проверены в редакторе.

## Косметический контакт

1. В редакторе выполни `Tools/Unreal/Art/prepare_vfx_material.py` после сохранения уровня и остановки PIE. Материал `/Game/Art/IronEcho/Materials/M_IE_ImpactSparks` создаётся как opaque/unlit с Instanced Static Mesh usage. Скрипт пока не запускался в UE.
2. Назначь его в `SparkMaterial` на AIEImpactVisualActor до BeginPlay, например в Blueprint defaults интеграции. Материал должен иметь настоящий cooked reference; не рассчитывай на строковую загрузку внешнего ресурса в packaged build.
3. После решения gameplay о контакте передай EventId, позицию в мировых сантиметрах, нормаль и интенсивность 0..1 в ShowConfirmedImpact. Без valid EventId/материала/BeginPlay эффект возвращает false. Повторный EventId игнорируется в ограниченной истории последних 512 событий.
4. Не передавай сырые пересечения позы, AnimNotify начала удара или предположение анимации как подтверждённый контакт. Этот актор не определяет попадания и не изменяет здоровье.

Пул ограничивает число экземпляров, Tick выключается при отсутствии искр, тени/навигация/коллизии отключены. Это простые короткие emissive штрихи; Niagara, звук, вмятины и локальные следы пока отсутствуют. Reduced motion очищает текущие искры и сокращает последующие события до двух коротких штрихов. Производительность ещё не измерена.

## Проверка на Windows

- Сборка Editor, затем packaged Development Win64 без отсутствующих модулей, шрифтов и материалов.
- Меню: каждое действие ровно один раз, фокус с клавиатуры, mouse/gamepad переходы, нет скрытого запуска боя при незавершённой калибровке.
- HUD: реальные события изменения здоровья/раунда; нулевые, отрицательные, NaN/Inf и пропавший источник не показывают выдуманные данные.
- Камера: реальный pivot, оба бойца, атаки противника, столбы/канаты, узкая дистанция, уничтожение/смена target.
- VFX: одно подтверждённое попадание, повтор ID, длительная серия, bounded history, reduced motion, отсутствие игрового damage/collision.
- UI: viewport 375/768/1024/1440, реальный DPI/шрифты/контраст ≥4.5:1, экранные цели ≥44px, фокус, screen reader и уменьшение движения.
- Сохранить результаты, скриншоты/видео и профиль FPS/VRAM. Ни один пункт выше пока не засчитан как UE runtime PASS.
